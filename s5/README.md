# 松下 S5 十秒镜头

配合一句口播的 10 秒纯 CG 镜头（1920×1080，24 fps，正好 240 帧，画面 2.39:1 遮幅）。口播本身不上屏：

> 六年，足够让 4K 从旗舰卖点变成基础配置，也足够让一台 14000 元的机身，掉到现在只剩个零头。

画面只放能复核的物料：发布报道的标题原文、各品牌国行首发价、闲鱼截图。每个数字的来源、日期和核实状态都在 `evidence/`（台账 `ledger.csv`，抽样 `xianyu-sample.csv`，说明 `evidence/README.md`）。

## 快速开始

预览：直接用 Chrome 或 Edge 打开 `s5/index.html`。字体和截图都打包成了 data URI，不联网也能看。空格播放/暂停，← → 逐帧，Shift + ← → 跳 1 秒；勾选项可以切换灰盒、朗读提示、遮幅、颗粒和运动模糊。

从头生成（需要 Node 18+、Python 3、ffmpeg 和 Playwright）：

```bash
python3 -I s5/tools/crop_xianyu.py     # 从 evidence/raw 裁卡片、打码（只在本地）
python3 -I s5/tools/build_assets.py    # → data/sample.js、build/cards.js
python3 -I s5/tools/build_fonts.py     # 改过画面上的字之后重跑：重新抽取字形
python3 -I s5/tools/build_single.py    # → s5/out/s5-storyboard.html，单个文件，双击即可预览和导出
node s5/render.mjs                     # → s5/out/s5.mp4
```

`s5-storyboard.html` 把字体、闲鱼卡片和导出库全部内联进一个约 6 MB 的文件，拷到哪台电脑都能直接用 Chrome / Edge 打开，不联网。里面有别人商品的截图，所以只放在 `out/`，不进 git。

## 导出

**在页面里导出**：预览页下方的“导出视频”。格式可选 MP4（H.264）、WebM（VP9）、PNG 序列；分辨率 1080p / 4K / 720p；帧率 24 / 25 / 30 / 60；码率可调；运动模糊可开关，遮幅和颗粒跟随预览设置。每一帧都按时间重新绘制，不是录屏，所以不会掉帧，任何帧率都准。MP4 / WebM 用浏览器自带的 WebCodecs 编码，需要最新版 Chrome 或 Edge。PNG 序列会让你选一个文件夹逐帧写入；不支持选文件夹的浏览器会打包成 ZIP。

**命令行导出**（做母版用，ffmpeg 编码，标 BT.709）：

```bash
node s5/render.mjs                          # H.264 MP4，24 fps，运动模糊开 → out/s5.mp4
node s5/render.mjs --format prores          # ProRes 422 HQ 10-bit，进剪辑用 → out/s5.mov
node s5/render.mjs --format png             # PNG 序列 → out/frames/
node s5/render.mjs --size 3840x2160         # 4K（任意尺寸，页面按该分辨率重绘）
node s5/render.mjs --fps 60                 # 60 帧
node s5/render.mjs --still 8.42             # 单帧 PNG
node s5/render.mjs --greybox --guide        # 灰盒预览：时间码、镜头号、朗读提示
node s5/render.mjs --letterbox 0 --grain 0 --mb 0
```

页面导出的视频色彩标签是 BT.709 原色 + sRGB 传递函数（浏览器画面本来就是 sRGB）；命令行导出统一标 BT.709。

## 质检

`python3 -I s5/tools/qc.py s5/out/s5.mp4 --nograin s5/out/qc-nograin-5-6s.mp4` 生成 `out/qc/README.md`，用测量代替肉眼：

1. 编码参数：尺寸、帧率、帧数、时长、色彩标签。
2. 电平：遮幅黑边、画面最暗和最亮（16–235 为标准，EBU R103 容许 5–246）。
3. 示波器：几帧的亮度波形和直方图。
4. 色带：按平台常见的 3 Mbps 再压一次，量暗部渐变里相同亮度的最长连续像素。对照片段用 `node s5/render.mjs --from 5 --to 6 --grain 0 --out out/qc-nograin-5-6s.mp4` 生成。

颗粒是直接加在画面上的 0–8 级亮度抖动（背景相应调暗 4 级，平均亮度不变）。当前结果：压缩后有颗粒最长 24 像素，无颗粒 248 像素。

## 冷启动观众测试

找 3 个没看过文案的人，静音看一遍成片（只看画面），看完马上问：

1. 这台相机当年的官方定价大约多少？（13,998 元，或“一万四左右”）
2. 它现在二手大约多少？（3,688 元，或“三千六七”）
3. 中间那张表在说什么？（同样能录 4K 60p 10bit 的相机，现在几千元的入门机都有）

3 个人三题都答对才算通过。哪一题有 2 个人答错，就说明对应的镜头读不清：加长停留，或放大那一处的字，再测一次。

## 改什么在哪

- **节奏**：`index.html` 顶部的 `T`（每个镜头和事件的秒数）；朗读提示是 `VO`，时间轴上的节拍标记是 `BEATS`。
- **对照表**：`CAMERAS`（机型、发布时间、国行首发价），来源见台账 L04、L10–L12。
- **价格和标题**：`LAUNCH`（官方定价）；S3 的报道标题和 S4 的说明在 `shot34`。二手价来自 `evidence/xianyu-sample.csv`，改完重跑 `build_assets.py`，中位数会自动重算。改过画面上的字要重跑 `build_fonts.py`。
- **配色和颗粒**：`C`、`GRAIN_K`。字体：`F`（思源宋体 / 思源黑体的子集）。

## 文件

- `index.html`：动画本体、预览播放器和导出面板
- `render.mjs`：逐帧导出脚本
- `evidence/`：证据台账、抽样表；`raw/` 和 `xianyu/` 是截图，只在本地
- `tools/`：裁切、统计、打包截图、抽取字形、打包单文件、质检的脚本
- `data/sample.js`、`fonts/fonts.js`：生成的数据和字体子集
- `vendor/`：mp4-muxer 5.2.2、webm-muxer 5.1.4（MIT，页面导出用）
- `build/`、`out/`：本地生成物，不进 git
