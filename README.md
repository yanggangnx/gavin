# 要求越多

用网页做的 16:9 横屏 3D 动效短片（1920×1080，30 fps，23 秒），可以逐帧导出成 MP4。

> 本来就想出去玩的时候，给自己、给朋友拍点好看的照片。结果越看测评，要求越多：要全画幅，要专业视频，镜头最好也一步到位。

画面里不直接出现这段文案，而是用数据讲同一件事：每一段只有一个小标签、一个大数字和几行参数，3D 物体上再用细线标出关键数值。

## 怎么用网页渲染 3D motion 视频

1. **固定画布。** 舞台是一块 1920×1080 的区域：底下一层 WebGL 画布（Three.js）负责 3D，上面一层 HTML 负责数据和标注。浏览器里预览时整体缩放，导出时 1:1 截图。
2. **每一帧都是时间的函数。** `render(t)` 根据时间 `t` 设置相机位置、零件位置、材质、灯光和每个数字，再渲染一帧。没有按真实时间走的动画，随机数也带种子，所以任意一帧都能原样重现。
3. **逐帧导出。** `render.mjs` 在本地起一个小服务器，用无头浏览器打开 `index.html?render`，对第 i 帧调用 `__motion.seek(i / fps)`，截图后通过管道交给 ffmpeg 编码成 H.264。

3D 部分全部用 Three.js 自带的几何体拼出来（圆角盒、圆柱、圆环），没有外部模型文件。影棚反射来自程序生成的环境光，照片、测评屏幕、镜头刻字和传感器都是运行时用 canvas 画的贴图。物体上的标注线是把 3D 坐标投影到屏幕上画的，所以会跟着物体和镜头移动。

## 快速开始

需要 Node 18+ 和 ffmpeg（macOS：`brew install ffmpeg`；Windows：`winget install ffmpeg`）。

```bash
npm install
npx playwright install chromium   # 已装 Google Chrome 可跳过，脚本会自动用它
npm run render                    # → out/yaoqiu-yueduo.mp4
```

有显卡的电脑上导出很快；没有显卡的服务器会用软件渲染 WebGL，23 秒的片子大约要 6 分钟。

预览：`npm run preview` 后打开提示的地址。不要直接双击 `index.html`：浏览器不允许从本地文件加载 JS 模块，会改用 CDN 上的 Three.js，断网时就看不到画面。预览页里空格播放/暂停，← → 逐帧，Shift + ← → 跳 1 秒，下方分镜可点击跳转。

更多导出参数：

```bash
node render.mjs --fps 60                 # 60 帧
node render.mjs --from 12 --to 16        # 只导 12–16 秒
node render.mjs --still 21.6             # 导出某一帧 PNG（做封面）
node render.mjs --crf 23                 # 文件更小（默认 18）
node render.mjs --format png             # 中间帧用无损 PNG（更慢）
```

## 改什么在哪

- **数字和参数**：`index.html` 里的六个 `<section class="blk">`，每个是一段的标签、大数字、单位和参数行。
- **会变化的数字**：`render` 末尾的 `setText(...)`（像素数、分辨率、光圈、倍数、测评计数），以及 `LEDGER`（合计的价格和重量）。
- **测评屏幕上的内容**：`REVIEWS` 数组；照片底边的拍摄参数：`EXIF`。
- **物体上的标注**：`build()` 末尾的 `S.callouts`，每条写了挂在哪个零件上、往哪个方向引线、文字和出现时间。
- **节奏**：脚本顶部的 `T`（每一段从第几秒开始），镜头运动在 `KEYS`（`[秒数, 水平角, 俯仰角, 距离, 看向的 x, y, z]`）。
- **配色**：影棚明暗在 `render` 开头的两组渐变色；机身颜色是 `porcelain`（白）和 `graphite`（石墨）。

## 加配乐或配音

导出的视频没有声音。可以在剪映里加，或者用 ffmpeg：

```bash
ffmpeg -i out/yaoqiu-yueduo.mp4 -i bgm.mp3 -c:v copy -c:a aac -shortest out/with-music.mp4
```
